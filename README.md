# ITMOGUESSR*

Сайт студенческого клуба GeoGuessr Университета ИТМО. Одностраничный статический сайт на Vite, TypeScript и CSS, без серверной части. Шрифты и брендовые изображения включены в сборку и не требуют внешнего CDN.

## Локальный запуск

Понадобится Node.js 22.12+ и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале.

```sh
npm run check    # Проверка TypeScript
npm run build    # Проверка и production-сборка в dist/
npm run preview  # Просмотр готовой сборки
```

## Где менять содержимое

Основные данные находятся в `src/config.ts`: контакты клуба, ближайшая встреча и будущие разделы. Неизвестные ссылки и данные мероприятия остаются `null`, чтобы сайт не показывал вымышленные адреса и даты. Заполняйте только подтверждённую информацию.

| Настройка | Что изменять |
| --- | --- |
| `siteConfig` | Описание клуба, город, подпись с координатами |
| `socialLinks` | Заменить `url: null` на подтверждённый HTTPS-адрес площадки |
| `nextEvent` | Заменить `null` объектом `ClubEvent`: название, ISO-дата с часовым поясом, место, описание и необязательная регистрация (`registrationUrl: null`, если её нет) |
| `futureFeatures` | Название, описание и будущий маршрут раздела; `status: 'available'` ставится только после создания страницы |
| `activities`, `faqs`, `navigation` | Направления клуба, ответы на вопросы и пункты меню |

Иллюстрации бренда находятся в `src/images/`. `public/brand-mark.png` — копия исходной эмблемы `src/images/ITMOGUESSR_avatar_1254.png`, используемая для favicon и превью ссылки; это не новый логотип. Стили и дизайн-токены — в `src/styles.css`, разметка секций — в `src/components/page.ts`, поведение навигации и анимаций — в `src/lib/interactions.ts`. Точка входа — `src/main.ts`.

## GitHub Pages

1. Загрузите проект в репозиторий GitHub, включая `package-lock.json`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в ветку `main` или вручную запустите **Deploy to GitHub Pages** на вкладке **Actions**.
4. После успешного выполнения workflow адрес появится в разделе **Settings → Pages** и в окружении `github-pages`.

Workflow `.github/workflows/deploy.yml` выполняет `npm ci`, проверку TypeScript, сборку и публикацию содержимого `dist/`. Относительный `base: './'` в `vite.config.ts` позволяет размещать сайт и в корне домена, и по адресу `https://<user>.github.io/<repository>/`. Собственный домен и `CNAME` не настроены.

При сборке в GitHub Actions шаг `configure-pages` передаёт подтверждённый адрес сайта (`base_url`) в `VITE_SITE_URL`. Vite автоматически формирует абсолютный `og:image`, `og:url` и canonical URL, включая подпапку репозитория. При локальной сборке без известного адреса картинка остаётся относительной, а canonical и `og:url` не добавляются.

Для другого хостинга задайте `VITE_SITE_URL` в `.env.local` перед сборкой: только подтверждённый полный HTTP(S)-адрес сайта, без параметров, фрагмента и данных авторизации. Шаблон `.env.example` оставлен без вымышленного домена; адрес не обязателен для локальной разработки. `.env.local` игнорируется Git.

Инструкции соответствуют официальным описаниям [настройки GitHub Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [выходов configure-pages](https://github.com/actions/configure-pages/blob/main/action.yml) и [публикации Pages-артефакта](https://github.com/actions/deploy-pages).

Для другого статического хостинга выполните `npm run build` и загрузите содержимое `dist/`.

## Развитие

Будущие разделы вынесены в конфигурацию: рейтинг (`/rating`), участники (`/players`), турниры (`/tournaments`), достижения и статистика. Пока это информационные элементы с пометкой «Скоро», без регистрации или платного доступа. Когда соответствующие страницы будут готовы, их можно подключить через конфигурацию и расширить отображение этих элементов.

На этой стадии нет авторизации, базы данных, API, рейтинга или турнирного сервиса. Для будущих полноценных URL на GitHub Pages потребуется добавить отдельные статические страницы или выбрать стратегию маршрутизации, совместимую с этим хостингом.
